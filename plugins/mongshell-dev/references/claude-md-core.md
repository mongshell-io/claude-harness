# 루트 CLAUDE.md 상시 코어 (정본)

플러그인은 세션에 상시 로드되는 컨텍스트를 주입할 수 없다 (플러그인 CLAUDE.md 는 로드되지 않음 — 공식 문서). 하네스가 전제하는 상시 규칙은 각 소비 프로젝트의 **루트 `CLAUDE.md`** 에 산다. 아래 블록을 복사해 삽입하되, 프로젝트에 이미 동등 조항이 있으면 그 조항은 지운다(중복 금지 — 프로젝트 고유 규칙은 블록 밖에 둔다). **`<…>` 자리표시와 「사람이 머지」 경로 나열만 프로젝트 값으로 채우고** 나머지는 정본과 바이트 동일하게 유지한다(자리표시가 남아 있으면 `/qa` 위험 경로 스크립트가 exit 1) — 낡음 판정은 마커만 보므로 본문 드리프트는 사람이 막는다.

## 자리표시 (저장소마다 다른 값)

| 자리 | 채우는 값 | 예 |
|------|-----------|-----|
| `<목업 규약 문서>` | 목업 상수·절차의 권위 문서 | `컴포넌트 영역 CLAUDE.md` · `docs/mockups/README.md` |
| `<verify 워크플로 name>` | 자동 머지 호출 파일 `workflows:` 와 같은 verify 워크플로 `name:` ([automerge-wiring.md](automerge-wiring.md)) | `verify` · `CI` |
| 「사람이 머지」 경로 나열 | **프로젝트 값** — 그 저장소 호출 파일 `deny_paths` 와 같은 집합. 블록에 적힌 값은 Drizzle 스택 앱의 공통값이라 그 스택이면 그대로 두고, 아니면 그 저장소의 마이그레이션 경로 · `.github/workflows/` 로 바꾼다 | 블록 그대로 |
| `<High 경로 나열>` | 「사람이 머지」 밖이지만 High 로 칠 경로. **요청 경로 파일(`src/proxy.ts` · `middleware.ts` 등)이 있으면 반드시 나열한다** — 나열이 없으면 `/qa` 위험 경로가 그 파일을 못 잡는다. 그런 경로가 하나도 없을 때만 그 문장(「**High 경로** = …」)을 통째로 지운다 | `` `.github/`·`Dockerfile`·`src/proxy.ts` `` |

**경로 나열 형식** — 「사람이 머지」·「High 경로」 문장은 `/qa` 가 스크립트([`scripts/risk-paths.sh`](../scripts/risk-paths.sh))로 읽어 위험 경로 패턴을 만든다. 그래서 형식을 지킨다: `**사람이 머지** =` / `**High 경로** =` 머리 뒤에 경로를 백틱으로 하나씩 적고(디렉토리는 `/` 로 끝냄, 그 밖은 파일) `가 바뀐 PR` 로 맺는다(종결자가 없으면 스크립트가 exit 1 — 줄바꿈 · 연속 공백은 접어서 읽는다). 경로 사이 괄호 설명에는 백틱을 쓰지 않는다 — 백틱 토큰은 전부 경로로 읽힌다.

```markdown
## 작업 규약 코어 (하네스 상시 규칙)
<!-- harness-core: 2026-11 -->

- **오케스트레이터**: 메인 세션은 탐색·계획·서브에이전트 관리·사용자 소통이 주 역할,
  실질 구현은 developer, 검토는 reviewer 에이전트에 위임. 위임으로 병렬성·컨텍스트 격리·
  독립 리뷰 중 하나라도 얻어지면 위임, 자명한 변경(한 줄·오타·기계적 교정)은 직접 편집.
- **1인 운영 전제**: 단순성 우선, 팀 협업 본질 패턴 디스카운트, 운영 부담 최소화.
- **스크립트 우선**: 결정적 판정(개수 비교·존재 확인·형식 검사)은 모델 추론이 아니라
  스크립트/bash 로 처리한다.
- **디버깅 원칙**: 증상 패치 전에 근본원인 — 데이터 흐름 추적 없는 fix 제안, 검증 없는
  원인 단정, 동시 다발 변경은 red flag. 같은 증상에 fix 3회 실패 시 아키텍처를 의심한다.
- **UI 목업 게이트**: UI 변경 인입 시 developer 위임 직전 목업 우선 여부를 판정한다 —
  트리거는 새 화면·큰 레이아웃 재구성만, 기본값 skip, 게이트락 아님. 사용자 "목업 먼저"
  pull 로 양방향 오버라이드 가능. 목업 합의 후 (필요 시) architect → developer 로 이어지며,
  상수·절차 권위는 <목업 규약 문서>.
- **머지 규약** (worktree 워크플로우 전제): PR 머지는 squash 만 — 사람이 머지할 때는
  `gh pr merge <N> --squash`, 자동 머지(아래 정책 노브 `automerge` 라벨)도 squash 다. `--delete-branch` 금지
  (worktree 의 `main` 점유와 충돌; remote 브랜치는 repo 설정 `delete_branch_on_merge` 가 자동 삭제, 자동 머지가
  머지한 PR 은 그 워크플로가 직접 지운다).
- **위험 등급**: PR 의 위험은 작성자가 아니라 **변경 파일**이 정한다. 등급은 셋 — **High** = DB 마이그레이션·요청 경로
  (proxy/middleware)·CI 워크플로(`.github/`)·배포 설정 변경(정책 노브의 사람이 머지 · High 경로 집합): 적용 순서와
  되돌리는 법을 PR 본문 Risk / How to revert 에 반드시 적는다. **Medium** = 경로로는 안 잡히지만 사람이 순서를 봐야 하는
  변경(데이터 소급·운영 스크립트·외부 응답 모양 변경): Risk 에 순서를 적는다. **Low** = 그 외. **등급은 라벨 여부를 정하지
  않는다** — 자동 머지에서 빼고 사람이 머지하는 것은 정책 노브의 사람이 머지 집합뿐이다.
- **정책 노브**: 커밋/PR trailer — `Co-Authored-By` **포함**, `🤖 Generated with Claude Code`
  **미포함**. 응답 톤 — 항상 존댓말. 커밋 메시지 — 한국어 conventional commits.
  `automerge` 라벨 — PR 을 만든 직후 붙인다 — 붙이면 <verify 워크플로 name> 성공 뒤 자동 squash 머지.
  **사람이 머지** = `drizzle/`·`src/lib/db/schema/`·`drizzle.config.ts`(DB 마이그레이션)·`.github/workflows/`(검사 정의와
  자동 머지 호출 파일 — 검사가 스스로 약해지는 PR 을 막는다)가 바뀐 PR — 하네스 공용 automerge 의 risk guard 가 라벨이
  있어도 거부한다. 이 집합의 권위는 이 줄이고 호출 파일 `deny_paths` 는 이를 따른다. 호출 파일은 `workflow_run` 이라
  기본 브랜치의 파일로 돌아 PR 이 자기 검사를 바꾸지 못한다.
  **High 경로** = <High 경로 나열>가 바뀐 PR — 사람이 머지 집합 밖이면 자동 머지 대상이되 Risk / How to revert 를 반드시 적는다.
```
