# verification-before-completion

**증거가 먼저, 주장은 그 다음.** 이번 응답에서 검증 명령을 돌려 출력을 읽지 않았다면 "통과한다" 고 말할 수 없다.

> 출처: [obra/superpowers](https://github.com/obra/superpowers) 의 `verification-before-completion` 을 이 하네스에 맞게 옮겼다 (MIT — `${CLAUDE_PLUGIN_ROOT}/LICENSE.superpowers`).

## 언제 적용하는가

- 완료·성공·수정됨을 뜻하는 모든 말 직전 — 표현을 바꿔도("문제없어 보입니다", "될 겁니다") 같다
- commit · push · PR 생성 · 작업 체크오프 · 다음 작업으로 넘어가기 직전
- developer 가 "완료" 를 보고했을 때 (메인 세션 쪽)

적용 대상은 메인 세션과 developer 다. reviewer 는 하네스 README "검증 명령 실행 책임" 에 따라 검증 명령을 실행하지 않는다.

상황이 트리거인 규율 스킬이라 명시 호출 없이 적용한다 (하네스 README "호출 방식").

## 게이트

```
주장하기 전에:
  1. 무엇이 이 주장을 증명하는가 — 명령을 특정한다
  2. 그 명령을 지금, 전체 범위로 돌린다 (이전 실행 결과 재사용 금지)
  3. 출력 전체와 종료 코드를 읽는다 — 실패 개수를 센다
  4. 출력이 주장을 뒷받침하는가
     - 아니면: 실제 상태를 증거와 함께 말한다
     - 맞으면: 주장을 증거와 함께 말한다
```

## 무엇이 증거인가

| 주장 | 필요한 증거 | 증거가 아닌 것 |
|---|---|---|
| 테스트 통과 | 테스트 명령 출력: 실패 0 · `exit 0` | 이전 실행, "통과할 것" |
| lint 깨끗 | lint 명령 출력: 오류 0 | 일부 파일만 확인 |
| 빌드 성공 | 빌드 명령 `exit 0` | lint 통과 (lint 는 컴파일을 보지 않는다) |
| 버그 수정 | 원래 증상을 재현해 보니 사라짐 | 코드를 바꿨으니 고쳐졌을 것 |
| 회귀 테스트 유효 | 수정을 되돌리면 실패, 다시 적용하면 통과 | 한 번 통과함 |
| 서브에이전트 완료 | `git diff` / `git log` 로 변경이 실제로 있음 | 에이전트의 "성공" 보고 |
| 요구사항 충족 | 성공 기준·이슈 요구를 한 줄씩 대조 | 테스트가 통과함 |

구체 명령(테스트·typecheck·lint·빌드)은 `docs/development.md` 또는 영역별 `CLAUDE.md` 가 권위.

## 하네스 안에서

- **메인 세션이 developer 보고를 받을 때** — REPORT 의 숫자 exit code 는 developer 가 낸 증거다. 메인은 그와 별개로 `git diff --stat` 으로 변경이 실제로 존재하는지, 변경 파일이 할당 범위와 맞는지 확인한 뒤 다음 단계로 간다. 결합 상태 판정은 `/plan` 의 2층 검증 모델(하네스 README "검증 명령 실행 책임")을 따른다 — `/plan` 이 재실행을 건너뛰는 경우, 메인은 "통과" 를 developer REPORT 의 숫자 exit code 를 인용해 말하고 직접 재실행하지 않는다. 증거의 출처를 밝히는 것이 이 스킬의 요구다.
- **developer 가 완료를 선언할 때** — UNDERSTAND 에서 적은 "성공 기준 1줄" 을 다시 읽고 대조한 결과를 REPORT 에 남긴다.
- **PR 직전** — 머지 전 검증의 권위는 `/qa --branch` 다. 이 스킬은 그 앞단에서 "검증 없이 완료라고 말하지 않는다" 만 지킨다.

## 멈춰야 하는 신호

- "아마", "~일 것", "~로 보인다" 로 상태를 말하려 할 때
- 검증 전에 만족을 표현하려 할 때 ("완료!", "완벽합니다")
- 검증 없이 commit · push · PR 하려 할 때
- 에이전트 보고를 그대로 믿으려 할 때
- 일부만 확인하고 전체를 말하려 할 때
- "이번 한 번만" 이라고 생각할 때

## 흔한 핑계

| 핑계 | 실제 |
|---|---|
| "이제 될 거예요" | 돌려 본다 |
| "확신합니다" | 확신은 증거가 아니다 |
| "lint 는 통과했어요" | lint 는 컴파일러가 아니다 |
| "에이전트가 성공이래요" | 독립적으로 확인한다 |
| "일부만 봐도 충분해요" | 일부는 아무것도 증명하지 않는다 |
| "표현이 달라서 해당 없어요" | 글자가 아니라 취지가 기준이다 |
